# Архитектура проекта

## 1. Общая информация

Проект представляет собой набор инструментов для чтения и анализа
биоинформатических файлов следующих форматов:

- FASTA;
- FASTQ;
- SAM;
- VCF.

Проект разрабатывается с использованием объектно-ориентированного подхода.

Для обработки больших файлов необходимо использовать генераторы там,
где это возможно. Это позволяет последовательно обрабатывать записи
файла без загрузки всего файла в оперативную память.

Использование специализированных библиотек для чтения FASTA, FASTQ,
SAM и VCF не допускается.

---

## 2. Общая иерархия классов

Классы для чтения файлов имеют следующую иерархию:

```text
Reader
├── SequenceReader
│   ├── FastaReader
│   └── FastqReader
│
└── GenomicDataReader
    ├── SamReader
    └── VcfReader
```

Дополнительно используются классы для представления биологических
последовательностей:

```text
Seq
└── FastqRecord
```

Классы `Reader` отвечают за чтение и разбор файлов.

Классы `Seq` и `FastqRecord` представляют отдельные биологические
последовательности и хранят относящиеся к ним данные.

---

## 3. Reader

`Reader` — общий абстрактный родительский класс для всех классов,
работающих с файлами.

### Атрибуты

`filepath: Path`

Путь к входному файлу.

Для работы с путями используется `pathlib.Path`. В коде не должны
использоваться абсолютные пути, зависящие от компьютера конкретного
участника проекта.

### Методы

#### `__init__(filepath: str | Path)`

Получает путь к входному файлу и сохраняет его в объекте.

#### `__iter__()`

Определяет возможность последовательного чтения записей файла.

Конкретный способ разбора записей зависит от формата, поэтому
реализация выполняется в дочерних классах.

---

## 4. SequenceReader

`SequenceReader` — абстрактный родительский класс для файлов,
содержащих биологические последовательности.

От него наследуются:

- `FastaReader`;
- `FastqReader`.

### Общие методы

#### `count_sequences() -> int`

Возвращает количество последовательностей в файле.

#### `average_length() -> float`

Возвращает среднюю длину последовательностей в файле.

Методы должны использовать итерацию по записям и не требовать
предварительной загрузки всех последовательностей в память.

---

## 5. Seq

`Seq` представляет одну биологическую последовательность независимо
от формата файла, из которого она была получена.

### Атрибуты

`seq_id: str`

Идентификатор последовательности.

`seq: str`

Биологическая последовательность.

### Методы

#### `__str__() -> str`

Возвращает строковое представление объекта.

#### `__len__() -> int`

Возвращает длину биологической последовательности.

### Важное правило

`Seq` не должен зависеть от конкретного файлового формата. В частности, класс `Seq` не должен требовать наличия символа `>`
в начале `seq_id`. Проверка особенностей FASTA-заголовка относится к ответственности
`FastaReader`.

---

## 6. FastaReader

`FastaReader` предназначен для чтения файлов формата FASTA.

Наследуется от `SequenceReader`.

### Основные задачи

- чтение FASTA-файла;
- проверка структуры FASTA-записей;
- обработка последовательностей, занимающих несколько строк;
- создание объектов `Seq`;
- последовательная обработка файла с использованием генератора.

### Методы

#### `__iter__() -> Iterator[Seq]`

Последовательно читает FASTA-записи и возвращает объекты `Seq`.

Заголовок FASTA-записи должен начинаться с символа `>`.

Символ `>` является частью формата FASTA и не должен храниться
в `seq_id` объекта `Seq`.

Методы:

- `count_sequences()`;
- `average_length()`

наследуются от `SequenceReader`.

---

## 7. FastqRecord

`FastqRecord` представляет одну запись FASTQ.

Класс наследуется от `Seq`, поскольку FASTQ-запись содержит
идентификатор и биологическую последовательность, но дополнительно
содержит информацию о качестве секвенирования.

### Дополнительный атрибут

`quality: str`

Строка символов качества из FASTQ-файла.

На этапе чтения качество сохраняется в исходном виде.
Преобразование символов качества в числовые значения выполняется
при необходимости анализа качества.

---

## 8. FastqReader

`FastqReader` предназначен для чтения и анализа файлов формата FASTQ.

Наследуется от `SequenceReader`.

### Основные задачи

- чтение FASTQ-файла;
- проверка структуры FASTQ-записей;
- создание объектов `FastqRecord`;
- обработка файла с использованием генератора;
- анализ качества секвенирования;
- построение графиков контроля качества.

### Методы

#### `__iter__() -> Iterator[FastqRecord]`

Последовательно читает FASTQ-записи и возвращает объекты
`FastqRecord`.

#### `plot_per_base_quality() -> None`

Строит график качества последовательностей по позициям
(per base sequence quality).

#### `plot_per_base_content() -> None`

Строит график содержания нуклеотидов в зависимости от позиции
(per base sequence content).

#### `plot_length_distribution() -> None`

Строит распределение длин последовательностей
(sequence length distribution).

Методы:

- `count_sequences()`;
- `average_length()`

наследуются от `SequenceReader`.

---

## 9. GenomicDataReader

`GenomicDataReader` — абстрактный родительский класс для файлов,
содержащих данные, связанные с геномными координатами.

От него наследуются:

- `SamReader`;
- `VcfReader`.

### Общие операции

Для SAM и VCF необходимы:

- работа с заголовком файла;
- получение определённых групп заголовка;
- работа с геномными интервалами.

### Методы

#### `get_header() -> list[str]`

Возвращает заголовок файла в виде списка строк.

#### `get_header_group(group: str) -> list[str]`

Возвращает строки заголовка, относящиеся к указанной группе.

Конкретная интерпретация групп зависит от файлового формата.

#### `fetch(chromosome: str, start: int, end: int) -> Iterator[dict]`

Последовательно возвращает записи, расположенные в заданном геномном
интервале или пересекающиеся с ним.

Конкретная реализация метода выполняется отдельно в `SamReader`
и `VcfReader`.

---

## 10. Система геномных координат

Для публичных методов проекта используется единая система координат:

**1-based inclusive.**

Это означает, что отсчёт позиций начинается с `1`, а обе границы
интервала включаются.

Например:

```python
reader.fetch("chr1", 100, 200)
```

означает участок хромосомы `chr1` от позиции `100` до позиции `200`
включительно.

### Проверка координат

Для геномного интервала должны выполняться следующие условия:

```text
chromosome не является пустой строкой
start >= 1
end >= start
```

При некорректных координатах должен возникать `ValueError`.

### VCF

Для VCF вариант относится к заданному интервалу, если его позиция
удовлетворяет условию:

```text
start <= POS <= end
```

### SAM

Для SAM запись выбирается, если геномный интервал выравнивания
пересекается с запрошенным интервалом.

При определении занимаемого выравниванием участка необходимо учитывать
информацию о выравнивании из SAM-записи, включая CIGAR.

---

## 11. SamReader

`SamReader` предназначен для чтения и анализа файлов формата SAM.

Наследуется от `GenomicDataReader`.

### Основные задачи

- чтение SAM-записей;
- обработка заголовка SAM;
- получение информации по группам заголовка, например `@PG` и `@RG`;
- подсчёт количества выравниваний;
- получение статистики по хромосомам;
- получение выравниваний в заданном геномном интервале.

### Методы

#### `__iter__() -> Iterator[dict]`

Последовательно читает записи выравниваний.

Каждая запись представляется словарём (`dict`), содержащим разобранные
поля SAM-записи.

#### `count_alignments() -> int`

Возвращает общее количество выравниваний в файле.

#### `count_by_chromosome() -> pandas.DataFrame`

Возвращает статистику количества выравниваний по хромосомам.

Для формирования статистики используется `pandas`.

#### `fetch(chromosome: str, start: int, end: int) -> Iterator`

Последовательно возвращает выравнивания, пересекающиеся с заданным
геномным интервалом.

---

## 12. VcfReader

`VcfReader` предназначен для чтения и анализа файлов формата VCF.

Наследуется от `GenomicDataReader`.

### Основные задачи

- чтение VCF-записей;
- обработка заголовка VCF;
- получение информации из отдельных групп заголовка;
- подсчёт количества вариантов;
- получение статистики по геномным регионам;
- получение вариантов в заданном геномном интервале.

### Методы

#### `__iter__() -> Iterator[dict]`

Последовательно читает записи о генетических вариантах.

Каждая запись представляется словарём (`dict`), содержащим разобранные
поля VCF-записи.

#### `count_variants() -> int`

Возвращает общее количество вариантов в файле.

#### `count_by_region() -> pandas.DataFrame`

Возвращает статистику количества вариантов по геномным регионам.

Метод является обязательной частью `VcfReader`, поскольку такая
статистика предусмотрена требованиями проекта.

#### `fetch(chromosome: str, start: int, end: int) -> Iterator[dict]`

Последовательно возвращает варианты, позиции которых входят в
указанный геномный интервал.

---

## 13. Обработка ошибок

Классы должны выдавать понятные исключения при возникновении ошибок.

### `FileNotFoundError`

Используется, если указанный входной файл не существует.

### `ValueError`

Используется, например, если:

- нарушена структура файла;
- запись имеет некорректный формат;
- переданы некорректные геномные координаты;
- отсутствуют обязательные данные.

### `TypeError`

Используется при передаче аргументов неподходящего типа.

Проверки, относящиеся к конкретному формату файла, должны выполняться
в соответствующем конкретном Reader.

---

## 14. Используемые библиотеки

Для чтения FASTA, FASTQ, SAM и VCF запрещено использование
специализированных библиотек для работы с биологическими
последовательностями и форматами геномных данных.

Для выполнения отдельных требований проекта допускается использование:

- `pandas` — для статистического анализа SAM и VCF;
- `matplotlib`, `seaborn` или `plotly` — для построения графиков FASTQ;
- `pathlib` — для работы с путями к файлам.

---

## 15. Автоматическое тестирование

Для автоматического тестирования используется `pytest`. Каждый участник
самостоятельно разрабатывает тесты для всех реализуемых им классов, включая
абстрактные и вспомогательные. Тесты добавляются в тот же Pull Request,
что и соответствующая реализация.

### Организация тестов

```text
tests/
├── data/
│   ├── example.fasta
│   ├── example.fastq
│   ├── example.sam
│   └── example.vcf
├── test_reader.py
├── test_fasta.py
├── test_fastq.py
├── test_sam.py
└── test_vcf.py
```

Файлы в `tests/data/` должны быть небольшими и содержать заранее известные
данные, для которых можно независимо определить ожидаемые результаты.
Для проверки ошибок допускается создавать дополнительные временные файлы.

### План тестирования классов

| Класс | Что проверить | Файл с тестами |
|---|---|---|
| `Reader` | Преобразование `str` и `Path` в `Path`; невозможность создать экземпляр абстрактного класса | `test_reader.py` |
| `SequenceReader` | `count_sequences()`, `average_length()`, обработку пустых файлов | `test_fasta.py`, `test_fastq.py` |
| `GenomicDataReader` | Абстрактность и необходимость реализации абстрактных методов | `test_sam.py`, `test_vcf.py` |
| `Seq` | Создание, валидацию данных, `__len__()`, `__str__()` | `test_fasta.py` |
| `FastqRecord` | Создание, наследование от `Seq`, хранение качества и соответствие длин последовательности и качества | `test_fastq.py` |
| `FastaReader` | Чтение FASTA, многострочные записи, генератор, некорректные записи | `test_fasta.py` |
| `FastqReader` | Чтение FASTQ, генератор, подсчёты, среднюю длину и три графика | `test_fastq.py` |
| `SamReader` | Чтение SAM, заголовок и группы, подсчёт выравниваний, статистику по хромосомам, `fetch()` с учётом CIGAR | `test_sam.py` |
| `VcfReader` | Чтение VCF, заголовок и группы метаданных, `count_variants()`, `count_by_region()`, `fetch()` | `test_vcf.py` |

Методы абстрактных классов можно проверять через их конкретные дочерние
классы. Отдельный тестовый файл для каждого класса необязателен.

### Общие требования

- Проверять правильность результатов, а не только отсутствие исключений.
- Проверять обработку некорректных данных и граничные случаи.
- Проверять повторное чтение файла одним объектом Reader.
- Проверять последовательную обработку записей генератором без необходимости
  предварительно загружать весь файл в память.
- Для `fetch()` проверять границы интервала и некорректные координаты
  согласно разделу 10.
- Проверять ожидаемые исключения согласно разделу 13.
- Для графиков FASTQ проверять корректность исходных данных и успешное
  построение графиков без интерактивного открытия окон.

Ожидаемое поведение в случаях, ещё не определённых архитектурой (например,
средняя длина для пустого файла или способ группировки регионов VCF),
необходимо согласовать до написания соответствующих тестов.

### Запуск

Из корневой директории проекта:

```bash
python -m pytest
```

Перед объединением Pull Request тесты соответствующего модуля должны
успешно проходить. После объединения веток запускается весь набор тестов.

## 16. Организация данных

В проекте используются две директории для хранения биоинформатических файлов:

`data/` — реальные файлы FASTA, FASTQ, SAM и VCF, скачанные из NCBI или других источников. Используются для демонстрации работы программы и проверки на реальных данных. Директория исключена из Git с помощью .gitignore, поэтому файлы не загружаются в репозиторий.

`tests/data/` — небольшие специально подготовленные файлы с заранее известным содержимым. Используются для автоматического тестирования классов с помощью pytest. Эти файлы должны храниться в GitHub-репозитории.

Каждый участник самостоятельно создаёт локальную директорию data/ и помещает в неё необходимые реальные данные. Тестовые файлы из tests/data/ должны быть доступны всем участникам команды.

## 17. Основные принципы архитектуры

1. Общая функциональность выносится в родительские классы.

2. Особенности конкретного файлового формата остаются в соответствующем
   Reader.

3. Классы чтения файлов и классы представления биологических
   последовательностей имеют разные обязанности.

4. Для обработки больших файлов предпочтительно использование
   генераторов.

5. FASTA и FASTQ используют общий интерфейс анализа последовательностей
   через `SequenceReader`.

6. SAM и VCF используют общий интерфейс работы с геномными интервалами
   через `GenomicDataReader`.

7. В публичном интерфейсе для геномных интервалов используется единая
   система координат `1-based inclusive`.

8. В проекте не используются абсолютные пути, зависящие от компьютера
   конкретного разработчика.

9. Имена классов, методов, переменных и файлов записываются на английском
   языке.

10. Пользовательская документация и описание архитектуры проекта
    оформляются на русском языке.
